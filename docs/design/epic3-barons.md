## 2. Architecture constraints every section below obeys

These come from section 1 and are the places an Epic 3 implementation would otherwise break replays.

1. **Persistence cannot live in the book.** `replenish()` erases it. Baron and rival effects are therefore **state in a world object that re-emits mods each round**, never edits to resting orders. Player market impact (the margin lever) is a decaying per-commodity `pressure_bps` accumulator in baron state, fed by the trades `StationMarket.execute` already returns.
2. **Step order (Proposed).** `_advance_crisis_deck` (existing) -> `round_advanced` -> in `M0Loop._on_round_advanced`: `world.advance_round(round, controller, market)` (barons sorted by id, then rival fleets sorted by id) -> `market.set_world_mods(world.market_mods())` -> `market.replenish()`. A bare `RunController` has no world, exactly as it has no crisis deck.
3. **Fixed fold order.** `_mods_for` folds `world_mods` first (barons by id, then rivals by id), then `crisis_mods`. Because depth and spread use per-step integer division, this order is part of the replay contract and gets a golden test.
4. **Hash stability.** With no `barons.json` loaded: `MAKER_ID` and `seed_book` behave byte-identically, `RunSave.capture` adds no key, no `schema_version` bump (`SaveStore` rejects other versions, never migrates). The `world` key is present only when attached, copying the `crisis` pattern. Any new `MetaProfile` field is read with a default when missing.
5. **Seeds.** Barons and rivals are world state: seed from `run_seed` (`StableHash.hash32("baron-<id>-<run_seed>-<round>")`), never `corp_seed`.
6. **Integers and sort order.** Money and bps are ints; any dictionary iterated for a decision is iterated in sorted key order; no wall-clock reads.
7. **Text.** Every new player-facing string needs `game/localization/agora_strings.csv` keys or `test_localization` and `test_i18n_audit` fail. Each UI-touching task in section 8 includes this.

## 3. Baron framework (for #15, Baron Framework design)

### 3.1 Data model (Proposed)

`game/data/barons.json`, loaded like `crises.json` (`CrisisDeck.load_data` pattern). Godot parses every JSON number as a float, so all reads go through `int()`.

```json

  "_placeholder": "Every number is a tuning guess for Ryan, in CR / bps / rounds.",
  "victory": {"barons_required": "all"},
  "takeover": {"float_shares": 1000, "threshold_shares": 501, "auction_cap": 100,
               "auction_discount_bps": 7000, "bankrupt_rounds": 6},
  "heat": {"decay_per_round": 1, "retaliation_at": 6},
  "barons": [
    {
      "id": "ares_heavy", "name": "Ares Heavy", "archetype": "short_squeezer",
```

Runtime state (`BaronState`, saved under `world.barons`): `treasury_cr`, `treasury_shares`, `inventory`, `margin_debt_cr`, `debt_cr`, `strain` (consecutive insolvent rounds), `pressure_bps{commodity}`, `heat` (player-caused, see 6.2), `holder` (`""` baron, `"player"`, or a rival id), `shares{holder}`, plus archetype scratch fields (squeeze countdown, hoard age, auction buffer). Integers and strings only, so `to_dict()`/`from_dict()` round-trip through JSON the way `CrisisDeck` does.

### 3.2 Anchoring a station

A baron **anchors** one station: its id replaces `MAKER_ID` for that station's books (`maker_for(station)`; unanchored stations keep `ares_heavy`, so M0 behaviour and hashes are unchanged until `barons.json` is present). Anchoring gives it three things: the maker identity on the book, the arrival toll, and the pipeline depth. Mars -> Ares Heavy, Earth -> Sol Central keep the current station names (Arcadia Foundries, Kennedy Elevator). Ceres is Titan's (see Question 3).

### 3.3 Monopoly privileges and how they show

- **Docking toll exemption (Proposed, ported from `lobbying.py`/`referee.py:2147`).** On arrival at an anchored station, anyone not in `toll_exempt` pays `docking_toll_cr` to SYSTEM, capped at CR held (the Python sim caps the same way). Rival fleets pay it too, so the toll is the baron's lever on competitors, not only the player. Holding the baron (section 5) puts the player in `toll_exempt`. Needs the travel loop (plan task 0).
- **Exclusive supply pipelines (Proposed).** For each `pipelines` entry the anchor's ask-side for that commodity gets `depth_bps` more depth, and **outsiders** pay `outsider_ask_bps` more on the ask. Insiders (baron, holder, fleets the baron allies with) see the base price. This needs a side-specific price field on mods (`ask_price_bps`, absent = 0, so existing mods are untouched); today a mod shifts bid and ask together.
- **In the order book.** `StationMarket.ladder()` rows gain `maker` (the participant id when one maker owns the level, else `""`) and the book tag line gains `ARES HEAVY PIPELINE +8% ASK` using the existing `CrisisDeck.tag_for`-style tag slot. `counterparty_name()` (today hardcoded to Ares) reads the world registry, so fills announce `SOL CENTRAL` where they do today for `ARES HEAVY`. A held baron shows `HELD` and `PIPELINE (YOURS)`.
- **Tuning rule.** A pipeline must make the anchor's own commodity cheap to *buy in volume* for insiders and expensive for outsiders, so holding a baron is a visible arbitrage edge worth the 120-round chase.

## 4. Archetypes (for #16, Baron Archetype AIs)

All three are **rules over existing primitives**: they read state, then emit `market_mods`, `BaronState` changes and headline strings. RNG is limited to magnitude and tie-break draws from `hash32("baron-<id>-<run_seed>-<round>")`; fire/no-fire timing that should feel fair goes through `Bags` keyed `baron:<id>`, like piracy and the crisis deck.

### 4.1 Ares Heavy (Mars): short squeezes and defense contracts

- **Defense contract (Proposed).** Every `contract_every_rounds`, Ares posts one contract: deliver `qty` of ORE or MACHINERY to Mars within N rounds for a bid wall `contract_bid_bps` above mid. The player may accept. This is a new obligation record in `BaronState`; it is *not* `MetaProfile.contracts`, and the Python `agora/contracts.py` needs reading before any further port. A missed delivery adds `contract_penalty_bps` of its value to doomsday principal debt (the only debt the player has).
- **Squeeze (Proposed).** The game has no short positions, so the squeezable exposure is the **open contract**. Rule: while an accepted contract has <= `squeeze_window_rounds` left and the player holds less than the remaining quantity, Ares emits a Mars mod for that commodity of `depth_bps = squeeze_depth_bps` and `price_bps = min(squeeze_price_bps_max, 1000 * rounds_short)`. This is the same shape as `localized_shortage`, so the HUD already renders it.
- **Determinism.** No RNG in the trigger. The contract's commodity and quantity use the per-round `DrawSource`.
- **Counterplay.** Stock cargo (from Earth or Ceres) *before* accepting; decline when Mars books are thin; deliver early. Squeeze price is capped, and a delivered contract pays a premium, so a prepared player profits. A counter-corner of Ares's pipeline commodity (section 5) also starves it of fulfilment stock.
- **As built (task 4, see row 4).** Implemented in `game/core/ares_heavy.gd`, driven by `Barons.advance_round(round, controller)` from `M0Loop._on_round_advanced`. Calls the doc left open:
  - **Deadline.** New param `contract_deadline_rounds` (6): a contract offered at round R is due at round R+6.
  - **Price.** Frozen when the offer posts: the anchor's `Transit.BASE_PRICES` (never the live book, which the player and the squeeze can move) times `1 + contract_bid_bps`, in whole CR. The contract pays `qty x unit price`, from Ares's treasury (floored at 0).
  - **Offer, answer, delivery.** One contract at a time. The offer halts the clock on a modal (A accepts, B declines; a crisis drawn the same round shows first). Delivery is automatic settlement, not a bid wall: the ship docked at Mars holding the **whole** quantity is paid on accepting, on docking, and at each round boundary. A declined offer leaves no state, so a run that always declines hashes as before.
  - **`rounds_short`** is the count of consecutive rounds inside the window in which the player held less than the quantity. Re-stocking resets it. `price_bps = min(squeeze_price_bps_max, 1000 x rounds_short)`.
  - **State, not computation, feeds the mods.** `advance_round` writes the contract and squeeze into `BaronState.scratch`; `market_mods()` only reads it, so a restored run re-emits identical mods and the books, which `replenish()` reseeds every round, carry the squeeze again.
  - **Penalty.** `contract_penalty_bps` of the whole contract value goes onto doomsday principal debt (`DoomsdayClock.add_principal`, which keeps the compounding base in step). It is a **consequence** event: charged in full, reports `forced_ch11` when it tipped the corp from solvent to insolvent, and never touches doomsday ticks.
  - **Lethal guard.** `Barons.penalize(rc, amount, origin)` clamps an `origin: "random"` fine so net worth stays at or above its pre-event value minus `consequence.random_max_loss_bps` (1500) and the corp stays solvent. Since #134 (Epic 3 steering) a random baron event carries NO fine at all (`Heat._fire` forces it to 0 and the shipped `fine_bps` are 0): it moves prices and stock only. The clamp stays as a backstop.
  - **Filing Chapter 11** cancels the open contract and squeeze: the obligation belonged to the failed corp.
  - **A baron the player holds** posts no contracts and never squeezes its holder.
  - **Counter-corner (built in task 8, see 5.2).** A player holding Ares's pipeline stock at Mars makes it cover from its own stock first, which starves the stock it would fulfil with.
  - **Built since (task 11):** heat from a missed contract (see 6). Not built: a replay recording that answers an offer was not exercised.

### 4.2 Titan Cryo-Hydro (Ceres): cornering volatile commodities

- **Volatile set.** FUEL and FOOD: widest cross-station spread (`Transit.BASE_PRICES`: FUEL 8.5-24.5, FOOD 10.2-27.5) and FOOD is the perishable (`Transit.PERISHABLE_COMMODITIES`).
- **Rule (Proposed).** State machine per commodity: `idle -> hoarding -> cornered -> releasing`.
  - `idle -> hoarding` when the anchor ask depth is <= `hoard_trigger_depth_bps` of nominal and treasury covers a round's buy.
  - `hoarding`: each round Titan removes up to `hoard_cap_qty` units of ask depth (a `depth_bps` mod, since it cannot edit the book) and adds the units to inventory, paying the ask from treasury.
  - `cornered` once inventory >= its corner share of system supply: the ask side is thinned and priced `corner_premium_bps` over mid.
  - `releasing` after `release_after_rounds` or when treasury strain trips: depth floods and price falls, which is also the margin-lever opening for the player (4.1/5.2).
- **Determinism.** Pure function of book depth, treasury and age. The only draw is the hold length jitter (+/- 1 round).
- **Counterplay.** The corner is an arbitrage signal: haul the commodity into Ceres and sell into the premium. Hoarded FOOD decays, so waiting works against Titan. A held player stock of the corner commodity drains Titan's treasury (lever 5.2a). `fuel_hedge` (`fuel_discount_bps` +1000) makes FUEL corners cheaper to survive once fuel is bought in play.
- **As built (task 5, see row 5).** Implemented in `game/core/titan_cryo_hydro.gd`, driven by `Barons.advance_round(round, controller, market)` from `M0Loop._on_round_advanced`. Calls the doc left open:
  - **Trigger.** The anchor's resting ask, read from the book at the round boundary (before the reseed), as bps of what the current mods seed (`StationMarket.ask_depth_ratio_bps`). So the player's own buying is what starts a hoard. `hoard_trigger_depth_bps` moved from the doc's 7000 to 8500: the Ceres ask carries the 15000 bps pipeline, so 7000 would need a 74-unit bite against a 100-unit hold. Without a market argument the trigger cannot fire. A cooldown (`cooldown_rounds`, 4) follows each release.
  - **Hoarding.** Titan removes about `hoard_cap_qty` units from the ask with a thinning `ask_depth_bps` mod (never more than that, the ladder rounds per level), pays the anchor's base price from its treasury and stocks the units.
  - **Corner.** Stock at `corner_inventory_qty` (FUEL 330, FOOD 300; the doc's "corner share of system supply" is a stock line here, there being no system supply figure): ask depth x0.4 and `price_bps` +`corner_premium_bps` on both sides, so stock hauled in and sold at Ceres sells into the premium. If decay drops the stock back under the line the premium lapses and Titan buys again.
  - **Release.** After `release_after_rounds` (6, +/- 1 from one draw seeded `hash32("baron-titan_cryo_hydro-<run_seed>-<round>")`, commodities drawing in sorted order) or when the treasury cannot cover a round's buy: for `release_rounds` (2) the ask floods (x2.0) and the price falls `release_discount_bps` (15%) while Titan sells up to `release_sell_qty` a round back down to its opening stock.
  - **FOOD decay link.** A perishable (`Transit.is_perishable`) loses `food_decay_bps` (5%, at least 1 unit) of Titan's stock each round it is hoarding, cornered or releasing; the total is reported on release (`HL_TITAN_SPOIL`).
  - **Random, never Chapter 11.** Every Titan event is origin `random`, and Titan only moves its own treasury and stock and the book mods, never the player's CR or debt, so none can force Chapter 11. The hoard is the baron's own strategy, not the failed corp's obligation (unlike Ares's contract), so it survives a filing. A held baron hoards nothing and emits no mods.
  - **Player's held stock draining Titan's treasury (built in task 8, lever 5.2a).** See 5.2.
  - **Not built:** `fuel_hedge` interplay.

### 4.3 Sol Central (Earth): rigged call auctions

- **Auction (Proposed port).** Every `auction_every_rounds`, Earth runs a call auction for one commodity: orders collected in the round uncross at one price, `find_clearing_price(bids, asks, ref_price)` ported from `agora/circuit_breaker.py:43` (maximise matched volume; ties by distance to `ref_price`, then lower price). Fills respect limit prices. The player's IOC orders at Earth during an auction round go into the buffer instead of sweeping the book.
- **The rig.** Sol Central controls `ref_price` (it prints the reference) and injects a balanced bid/ask pair at the tie edge so the volume-maximising price lands up to `rig_bps_max` toward its own inventory side. The shift is deterministic: it picks the candidate price inside `rig_bps_max` that maximises its own mark-to-market, ties by lower price.
- **Determinism.** No RNG in the clearing. The buffer is sorted by `(limit_price, seq)`.
- **Counterplay.** The player sees an **indicative price** before the auction closes (`indicative_leak`: full, or delayed by one round on a perk). A limit order simply does not fill outside the rigged price, so a disciplined player loses only the missed trade. Orders can be withdrawn until close. Rigged magnitude is shown as indicative-vs-last, so the rig is legible. Holding Sol Central ends the rig and hands the player `ref_price`.

- **As built (task 6, see row 6).** Implemented in `game/core/sol_central.gd`, driven by `Barons.advance_round(round, controller, market)` from `M0Loop._on_round_advanced`. Calls the doc left open:
  - **Port and parity.** `SolCentral.find_clearing_price` is a line-for-line port of `agora/circuit_breaker.py:43`. `tools/golden/gen_clearing.py` (a sixth generator in `check_drift.py`) runs the real Python function over 16 cases into `game/tests/golden/clearing/clearing_price.json`, and `test_sol_central.gd` replays them.
  - **Schedule is derived, not stored.** The auction for round R is open while the clock is in round R, for R = 5, 10, ... 40 (a multiple of `auction_every_rounds`); its commodity is one draw from `hash32("baron-sol_central-<run_seed>-<R>")` over Sol Central's two stock commodities (FOOD, FRAG). It closes at the boundary into R+1, before the books are reseeded. The only saved state is `scratch["buffer"]`, written only while it holds an order, so a run that never queues one hashes as before.
  - **Buffer.** At Earth, in an auction round, a gamepad order on the auctioned commodity is a limit order (the focused level's price) queued instead of sweeping the book. It does not fire `order_executed` (no fill line, no bell) and has no escrow: it is checked against CR, hold room and cargo at submit and again at the close, so a queued order cannot push the corp into automatic Chapter 11. Buffer order is `(limit, seq)`.
  - **The cross.** Buffered orders plus Earth's resting book go through the port; fills are price-time, resting maker orders first, one price for everyone, at most the quantity asked, never outside a limit.
  - **The rig.** The honest price comes from the port. Sol Central then injects one balanced bid/ask pair, larger than all real volume, at the price in `[honest - rig, honest + rig]` that is best for its stock (higher while it holds the commodity, lower when it is out, ties to the lower price); `rig` is `rig_bps_max` of the honest price, at least 1 CR. The port is run again with the pair to confirm that price is the unique volume maximiser, then the pair is dropped (it trades with itself). Consequence: a buyer's limit below the printed price lapses, and a seller whose limit is above it lapses; nothing else moves. Sol Central's treasury and stock follow the fills.
  - **Indicative row.** The Earth sidebar shows `AUCTION <commodity>: CLOSES RD n`, `INDICATIVE p CR  REF r  +x%` (the printed reference is the anchor's base price), each queued order, and `MISSES` on one the printed price walks past. `indicative_leak: "delayed"` hides the price (`INDICATIVE HIDDEN`); the perk that would restore it is not built.
  - **Withdraw.** B on the Market tab takes the queued orders back (a second B leaves the tab). Departing Earth, a Chapter 11 filing and taking the baron also drop them; a held baron runs no auction.
  - **Chapter 11.** No Sol Central event touches the player's debt, so none can force Chapter 11, random or otherwise; `Barons.penalize` is not used. The only cost is the price of a trade the player chose to queue.
  - **Not built:** a held baron handing the player `ref_price` (a held baron simply runs no auction), the `delayed` leak perk, rival fleets in the cross.

## 5. Takeover and insolvency (for #17, Hostile Takeover & Insolvency)

### 5.1 What the Python sim does (Ported source)

`agora/corporate.py`: distressed corps auction treasury shares at 0.7 x max(NAV, mark, 10) up to 100 a round (`AUCTION_CAP`, `DISCOUNT`, `PRICE_FLOOR`); 51% (`live_shares // 2 + 1`) of a corp's stock absorbs it (`_takeovers`, :502); bankruptcy after `BANKRUPT_ROUNDS = 10` indebted rounds with no treasury shares (:36); predatory loans at 20% default interest, due in 5 rounds, whose default adds the due amount to corporate debt (`create_loan_offer` :1025, `_check_loan_maturities` :1234); tender offers and a poison pill at >30% stake (:606, :736). Margin: 120% initial, 105% maintenance, forced liquidation below it (`agora/equity.py:50`, `liquidate_loan`). The game guide notes a raider "can't reach 501 from the market alone" at live defaults, which is why distress is the real route.

### 5.2 Three levers

The baron has `float_shares` (1000), most of them in its own treasury. The player gains shares only through the distress auction (up to `auction_cap` a round at a discount, split by cash with rival fleets) or by tendering for rivals' stakes. So each lever is a way to **make the baron distressed**.

- **a. Corner its float.** If the player holds >= the baron's corner quantity of its `float` commodity at the anchor, the baron must buy cover at squeezed prices each round: `treasury -= shortfall_qty * squeezed_ask`. The player pays carry (capital tied up, FOOD decay).
- **b. Margin liquidation.** Collateral value = inventory marked at the anchor mid after `pressure_bps`. Below the 105% maintenance ratio against `margin_debt_cr`, the baron force-sells a fraction of inventory into its own book (a price-crash mod for 2 rounds, haircut 50%), burning treasury. The player triggers it by dumping the collateral commodity at the anchor; the pressure decays by integer halving each round, because `replenish()` would otherwise erase it.
- **c. Predatory credit.** The player offers a credit line (default 20% interest, due in 5 rounds). A baron accepts only above a `strain` threshold. If treasury < due at maturity it defaults: the due amount joins `debt_cr`. This is the first loan product in the game.

- **As built (task 8, see row 8).** Implemented in `game/core/levers.gd` (`Levers`), stepped by `Barons.advance_round` after the archetypes and before the takeover core, so a baron a lever just broke is assessed, and put up for sale, in the same boundary. Numbers are in a new `levers` block in `barons.json` (placeholders for Ryan; validated, optional, defaults in `Levers.DEFAULTS`). Calls the doc left open:
  - **Everything lands in `debt_cr`, because insolvency is `total_debt > liquidation_value`.** A baron with no debt is never insolvent however empty its treasury, so each lever's unpaid remainder goes through `Barons.add_debt`, and a treasury never goes negative.
  - **a. Corner.** At a round boundary, with the player docked at the anchor and holding at least `corner.hold_qty` (60; the hold is 100) of one of its pipeline commodities, the baron must buy `corner.cover_qty` (100) units of cover. Stock first (this is the counter-corner of 4.1: Ares's stock is starved), then the rest at the anchor's BASE price plus `corner.squeeze_bps` (+50%). Cash it cannot pay becomes system debt. The book shows it as an ask-side premium and a thinned ask (`ask_price_bps`, `ask_depth_bps`), never a bid change, so a corner cannot be turned into a selling price. It ends when the player leaves, sells under the hold, or takes the baron. The player's carry is the capital in the hold and the dock time; there is no separate decay charge (FOOD decay of the player's own cargo is not modelled in play).
  - **b. Margin.** A sale of a commodity in a baron's stock at its anchor adds `margin.pressure_per_unit_bps` (40) per unit to `pressure_bps[commodity]` (a field `BaronState` already saved, empty until used), capped at `margin.pressure_max_bps` (6000). It is fed from `M0Loop._on_order_executed`, so it needs no new input. The accumulator halves each round (integer, erased at 0) and is re-emitted as a `price_bps` mod. Collateral is the stock marked at `Piracy.REF_PRICE` (the Chapter 11 valuation) less the pressure; the base Mars prices would put Ares under water with nobody touching it (7,710 CR against a 9,450 CR maintenance line). A call needs pressure on a collateral commodity (a baron nobody leans on is never called) and collateral under `margin.maintenance_bps` (105%) of `margin_debt_cr`. Ares opens at 111%, Titan 125%, Sol Central 169%, so Ares is the fragile one. A call force-sells `margin.liquidate_bps` (30%) of each pressured commodity at the 50% haircut, pays the loan down, charges `margin.fee_bps` (10%) of the notional to the treasury, writes off what the remaining stock no longer covers as system debt, and crashes the book (`margin.crash_bps`, -15%) for `margin.crash_rounds` (2). No new call while the crash is on the book; while pressure persists the cascade repeats every third round.
  - **c. Credit line.** The `m0_credit` action (R3 / G) extends the standard line: `credit.line_cr` (10,000) at `credit.rate_bps` (20%), due in `credit.term_rounds` (5). "Accepts only above a strain threshold" cannot use `strain` (it counts insolvent rounds, so only an insolvent baron would borrow): the baron accepts while `strain` > 0 or its treasury is at or under `credit.accept_below_bps` (70%) of its opening treasury, which is what a corner produces. It spends `credit.spend_bps` (75%) at once, so a default is reachable. At maturity it repays if the treasury covers the amount due; otherwise the amount due joins its debt with the player as creditor, so bankruptcy settlement and the takeover read the claim. Refused (`NO_BARON`, `HELD`, `OPEN`, `NOT_PRESSED`, `NO_CR`, `WOULD_BANKRUPT`: the lent CR is not in the Chapter 11 snapshot, so the corp is checked before it can be left insolvent). A bankruptcy calls an open line in (its amount due becomes the claim); a takeover cancels it; a Chapter 11 filing ends the corners and the line.
  - **The chain.** Corner, then credit, then default, then insolvency, then the distress auction, with no staged debt, is a test (`test_a_corner_then_a_loan_then_a_default_ends_in_a_distress_auction`) and the `levers-distress` screenshot: about 28 rounds against Ares.
  - **`hostile_buyout_line`** is enabled (Monopoly Drive, tier 3, still needs a tier-2 prerequisite). It adds the `takeover_threshold_shares` stat (-50), now `live` in `Parachutes.STATS`: `Takeover.threshold_for` gives the player 451 where a rival stand-in still needs 501. It unlocks tender offers: with no distress lot on offer the existing `m0_shares` action tenders for up to `tender.cap` (50) a round of the public float (the float less the treasury's and every holder's: 400 for Ares) at `tender.premium_bps` (150%) of NAV per share, at least the auction floor. The cash goes to the sellers, not the treasury, so a tender cannot cure a baron's insolvency; 400 public shares is under 451, so the last 51 still come from distress. Tendered shares return to the public float, not the treasury, on a Chapter 11 filing.
  - **Ryan's rule (9.4).** Nothing a lever does is random, and none can put the player into Chapter 11: the only thing it asks of the player is CR for a credit line, refused before it could leave the corp insolvent.
  - **Controls.** One new action, `m0_credit` (R3 / G, a Steam Deck right-stick click); nothing locked was rebound.
  - **Built since (task 11):** heat from the levers (see 6). **Not built:** the `corrupt_regulator` loan rate (`interest_bps` is per-minute doomsday interest; it is not applied to the credit line), tender offers for a rival's stake (no rivals before task 10), the `delayed` indicative-leak perk and baron upkeep (which would move every pinned world hash).

### 5.3 Insolvency and settlement (Proposed)

- Baron solvency uses **`Chapter11.assess`** on `{cr: treasury, cargo: inventory, ships: [], doomsday: {principal_debt: debt_cr}}`, so one definition of insolvent covers player and barons, 50% haircut included.
- Insolvent for `bankrupt_rounds` (6 here, 10 in the Python sim, because the run is 40 rounds) with no treasury shares left -> **bankrupt**: inventory liquidates at the haircut, proceeds pay creditors pro rata by claim, the largest claim holder (ties: sorted id) becomes `holder`.
- 501 shares -> **takeover** at once (Python `_takeovers`): the raider absorbs treasury, inventory, debt and credit claims; a loan the raider itself made cancels out (Python does the same).
- On either outcome the holder gains the privileges (toll exempt, pipelines) and **rent**: the anchor's maker spread accrues to the holder each round (Proposed; the rate is a tuning number).
- **Filing Chapter 11 forfeits holdings.** A filing founds a new corp, so held barons revert to NPC control with treasury reset to 40%, deterministically. The world and its seeds persist (section 2.5).
- **`hostile_buyout_line`** (disabled today) becomes the lever perk: enabling it adds a `takeover_threshold_shares` stat of -50 and unlocks tender offers. New stat, so it joins `Parachutes.STATS` as `pending` until #17 (Hostile Takeover & Insolvency) lands.

- **As built (task 7, see row 7).** Implemented in `game/core/takeover.gd`, stepped by `Barons.advance_round` after each archetype (barons by sorted id). Calls the doc left open:
  - **Distress.** A baron is distressed while `Chapter11.assess` on its books says insolvent (`strain` counts the rounds). It offers `min(treasury_shares, ceil(shortfall / px), auction_cap)` shares at `px = max(1, max(NAV per share, auction_price_floor) x auction_discount_bps)`, written at the round boundary into `scratch["distress"]` and bought during the next round. NAV is negative while insolvent, so the price is the floor (10 CR) x 70% = 7 CR; the Python sim's `mark` term has no equivalent here. New tunables in `barons.json`: `auction_price_floor` (10, the Python `PRICE_FLOOR`), `reset_treasury_bps` (4000), `rent_units` (100), `rent_spread_bps` (600).
  - **Buying.** `Barons.buy_shares(rc, station, n)`; the UI action is `m0_shares` (L3 / F) at the docked station. A purchase takes only what the threshold needs (the 501st share takes the baron, the rest of the lot stays on offer) and is refused (`NO_OFFER`, `NO_CR`, `HELD`, `WOULD_BANKRUPT`) before it can leave the corp insolvent, since shares are not in the Chapter 11 snapshot. Rival fleets bid through the seam `Barons.rival_bids` (none today); `Barons.sell_auction_shares` is the stand-in.
  - **Takeover.** The holder absorbs the treasury into CR and the debt onto doomsday principal (a claim the taker itself held cancels), as a consequence of the player's own purchase: `forced_ch11` is reported when it tipped the corp from solvent to insolvent, and the filing that follows forfeits the baron. The baron's stock stays in its warehouse (the hold is 100 units, Ares alone stocks 500). Its archetype scratch (contract, squeeze, auction buffer) is dropped.
  - **Bankruptcy.** `bankrupt_rounds` (6) strained rounds with `treasury_shares == 0`. Liquidation value (haircut) pays creditors pro rata by claim, the rounding remainder to the largest claim; the largest claim holder, ties by sorted id, becomes holder. Claims live in `scratch["claims"]`; debt no creditor is named for (all of it today) is the system's, and a system-largest bankruptcy reorganises the baron under NPC control (treasury at `reset_treasury_bps` of its opening, opening float, no stock). `Barons.add_debt(id, amount, creditor)` is the door the levers (task 8) use.
  - **Rent.** A baron the player holds pays its holder, each round, `rent_units` of each pipeline commodity's BASE anchor price at `rent_spread_bps` (Ares: 181 CR a round).
  - **Forfeit.** Filing Chapter 11 reverts held barons (treasury `reset_treasury_bps` of the opening, opening stock and float), returns partial stakes to the treasury shares and strikes the failed corp's claims. Rival-held barons are untouched.
  - **Random, never Chapter 11.** No takeover-core step is random. The only paths that can fail the corp are the player's own purchase (refused when it would) and the debt a takeover assumes (reported as `forced_ch11`).
  - **Built since (task 8, see 5.2):** the levers that make a baron distressed, and `hostile_buyout_line`.
  - **Not built:** rival bids; baron upkeep (`upkeep_cr_per_round` is still not charged, which would move every pinned world hash).
  - **As built (#134, Epic 3 steering: the sealed-bid distress auction).** Replaces the fixed-price first-come lot. `Takeover.fill` clears a lot: highest bids first, ties by sorted id, every winner pays the lowest winning price (the reserve when the lot is not oversubscribed; 1 CR on a forced lot). The lot is written at a boundary, bids are placed during the next round (`Barons.submit_bid`; the `m0_shares` key bids the whole lot at "your value" and each further press in the same lot raises the top price by `takeover.bid_step_bps`, so there is no new binding), and it clears at the following boundary (`Takeover.clear_lot`), cutting a player bid they can no longer pay. `Takeover.value_per_share` is the one valuation: NAV per share (at least the price floor) x (1 + `takeover.control_premium` at the bidder's stake as a share of its own threshold). It sets the fleets' top bids (`Rivals.bids`: only barons anchored where the fleet trades, never above value, bounded by cash and by `Chapter11` headroom; no random draw, so `bid_chance_bps` is gone), a fleet's asking price in recapture, and the HUD "your value" row. `Takeover.recapture` (the same key at a baron a fleet holds) sells when the offer is at least the fleet's own valuation; a fleet pushed under its threshold loses control. The HUD reads each bidder's stake, the last clearing price and every fleet's CR against its debt. A fleet takes `Chapter11.assess` each boundary (`Rivals.health`; opening `debt_cr` per fleet in `barons.json`); after `fleet_bankrupt_rounds` (4) insolvent rounds `Rivals._liquidate` ends it: its CR and cargo go, a baron it held reverts to NPC control, and its shares become `scratch["forced"]` for that baron's next lot with no reserve. A gone fleet stays in the save (`gone`) but not in `rival_ids()`. Docking tolls at a player-held baron already drain fleets. New state keys are written only while non-default, so a world that never distresses a baron hashes as before. Not built: raids as a drain on fleets (privateer hire does not exist yet); the card is crowded in the crowded-lot case (a credit-line chip can scroll off the sidebar).

## 6. Rival fleets (for #18, Rival Syndicate Fleets)

### 6.1 Model (Proposed)

`RivalFleet`: `id`, `cr`, `cargo`, `route` (origin, dest, arrival round), `trait`, `stance`. Fleets are abstract (no ships array) and trade via a generalised `StationMarket.execute_as(participant_id, ...)`; today `execute` hardcodes `PLAYER_ID` and `"player-%d"` order ids. They run `Transit.get_route` and `calculate_trip_rounds` for timing and use `Piracy.hire` for bounties, so they cannot do anything the player cannot.

- **Spatial arbitrage.** Each idle round a fleet scores every route by `(dest_mid - origin_mid - fuel_cost - toll) * qty` using book mids, picks the best, sorted-id tie-break, and departs. Alignment windows (`Transit.get_alignment_windows`) are public, so fleets exploit them predictably.
- **Front-running (trait `front_runner`).** When the player departs with cargo of value >= a threshold, any `front_runner` that can arrive at the destination in <= the player's trip rounds *and* has cash pre-positions: it emits a destination mod (`depth_bps` down on the commodity for 2 rounds) and a GalNet line on arrival. It can only react to the player's **departure** (treated as public: the tactical map projects fleet transit positions, `game/ui/sol_tactical_map.gd:6`; not verified in play); it cannot read resting orders, because the player has none (IOC only).
- **Privateer bounties (trait `privateer_sponsor`).** If a haul's `Piracy.cargo_value` >= `VALUE_REF` (10,000 CR), the cargo is unescorted and the route is a belt lane, a fleet with >= `PRIV_COST` (750, per code) calls `hire(rival_id, "player", round, cr)`. Effect is the existing +0.15 raid odds for 20 rounds. The player can see it via the existing "secret until traced" `PRIV_TRACE` roll, or buy escorts (-75% odds). The player may sponsor against rivals the same way.

### 6.2 Heat

Player actions that hurt a baron (levers a/b/c, bounties) raise that baron's `heat`; it decays 1 a round. At `retaliation_at` the baron queues a **consequence** event (section 7). Rivals' bounty targeting reads the same heat. Heat is per corp: a new corp (Chapter 11) starts at 0, since the world survives but the grudge belongs to the failed corp.

### 6.3 Determinism for replays and save hashes

- Fleets and barons are pure functions of `(run_seed, round, world state, player state)`. Replays record player inputs only (`replay.gd`); the AI re-derives identically, so no AI input is ever recorded.
- All decisions use sorted ids and integer bps. Per-fleet draws use `hash32("rival-<id>-<run_seed>-<round>")` into a fresh `NativeDrawSource`, so there is no persistent stream that a skipped round could desync.
- The world state is serialised under the `world` key, present only when attached; `state_hash` covers it via `canonical()`. New golden fixtures (the mod fold order lives in `game/tests/fixtures/world/fold_order.json`, not under `tests/golden/`, which `check_drift.py` reserves for referee-generated parity fixtures) pin: mod fold order, a 40-round baron+rival run hash for two seeds, and a save-at-round-N/restore/continue hash equal to the uninterrupted one.

- **As built (task 11, see row 11).** Calls the doc left open:
  - **Front-run.** Triggered only by the player's departure (`Barons.react_to_departure`), never by resting orders. A `front_runner` qualifies when the player's whole hold is worth at least `front_run_min_value` (1,000 CR, `Piracy.cargo_value`), it can reach the destination in no more rounds than the player's trip, and it keeps `front_run_min_cr` (3,000) after fuel and tolls. It then front-runs INSTEAD of its ordinary reaction; a fleet that does not qualify, or loses its chance draw (`front_run_chance_bps`, hash32 `rival-front-<id>-<run_seed>-<round>`), reacts exactly as in task 10. It sails (fuel, belt toll, docking toll) as a flagged voyage (`route.front`), and on landing, at the START of that round's boundary and before the reseed, the commodity's depth on the destination book is `front_run_depth_bps` (6000, i.e. -40%) for `front_run_rounds` (2) as a depth mod emitted after every baron's mods, with one GalNet line and a `KESSLER FRONT-RUN -40% DEPTH` desk tag. A fleet already docked at the destination starts at once (line at departure, dent from the next reseed). The most valuable commodity aboard (sorted tie-break) is the one dented. State: `RivalFleet.front`, saved only while it exists.
  - **Bounty.** Same trigger. Conditions: the lane is a belt lane, the hold is unescorted (there is no escort in play, so always), the sponsor has `Piracy.PRIV_COST` (750) and its chance draw passes (`bounty_chance_bps`, `rival-bounty-...`), and the hold is worth at least `bounty_min_value`. **Deviation from the doc:** the doc's floor is `VALUE_REF` (10,000 CR), which a 100-unit hold can never reach (the dearest unit is 21.2 CR, so the cap is about 2,120 CR), so the floor is a placeholder of 1,500 CR. Each point of total baron heat lowers it by `bounty_heat_value_step` (150): "rivals' bounty targeting reads the same heat". The hire goes through `Piracy.hire` on a world-owned desk, so one contract per sponsor and one per target hold; the contract is the existing +0.15 raid odds for 20 rounds (`Barons.bounty_raid_odds_bps`; `Piracy.chance` reads it through `active_contract`). **Raids are real since #134 (Epic 3 steering).** On each departure with the contract standing and a hold worth at least `rivals.raid_min_value` (1,500 CR), `Rivals._try_raid` rolls `Piracy.roll_departure` on an ephemeral desk seeded `hash32("rival-raid-<run_seed>-<round>")` that carries the world's contracts (so no bag state needs saving; the contract's raid count and trace are written back). The demand is auto-settled until a modal exists: the ransom (15% of the hold's value) is paid when the player holds it, else cargo is surrendered and lost. A traced raid fines the sponsor. There is still no player hire button. It is secret until traced: each round a standing contract is traced with `bounty_trace_bps` (1,000 = `PRIV_TRACE`, draw `rival-trace-<contract>-...`), which posts a GalNet line and shows a `BOUNTY ON YOU` chip. Contracts persist under the world's `bounties` key, only while any exist. The player sponsoring a bounty is `Barons.sponsor_bounty(rc, fleet_id)` (750 CR, refused when it would leave the corp insolvent): it raises heat on the baron anchoring the target fleet's dock by `heat.bounty_sponsored`. It has no key, so Epic 4 controls are unchanged.
  - **Heat.** `BaronState.heat` (already saved), raised only when a lever actually fires, never by a sale's pressure accrual: a corner round charged (`corner_round` 2), a margin call executed (`margin_call` 3), a credit line opened (`credit_open` 1) or defaulted (`credit_default` 3), a missed defense contract (`missed_contract` 4, the row 4 "not built"), a sponsored bounty (`bounty_sponsored` 3). Only a baron running itself takes heat (a held baron takes none and its heat is cleared). It decays `decay_per_round` (1) at the boundary, after the levers, so a held corner nets +1 a round and retaliation is about six rounds out. At `retaliation_at` (6) the baron queues a consequence (`scratch.retaliate`, written only while queued) and a GalNet line warns the player; the event lands at the next boundary and heat drops to `reset_to` (0), so it does not re-fire every round. A Chapter 11 filing zeroes every baron's heat and queue, ends the bounties on the failed corp's ship and drops its live consequence events (`Barons.forget_corp`).
